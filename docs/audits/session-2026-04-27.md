# Sessão 2026-04-27 — Mobile-first migration (Fases 1-3 entregues, Fase 4 pendente)

Sessão inteira focada em virar o app de **desktop-only** pra **mobile-first**. Saída: 3 deploys consecutivos pra prod, 47 specs Playwright criados/atualizados, 1 bug crítico do `/home` corrigido, 1 fase ainda pendente (admin no phone).

---

## Diagnóstico inicial — o que estava quebrado

Auditoria visual+grep do projeto encontrou:

1. **Sem `<meta viewport>`** em `app/layout.tsx` → mobile escalava todo layout (Safari iOS abria o app numa "viewport desktop" simulada)
2. **Sidebar 248px fixa em todas rotas** → em phone restavam ~120px úteis
3. **Layouts grid `1fr 320px`** sem variant mobile (`/approval/[id]`, `/home`, etc.)
4. **Tabelas admin** sem scroll-x ou variante card
5. **`body { overflow: hidden }` global** quebrava scroll natural mobile
6. **Padrão CSS desktop-first** com `@media (max-width: 900px)` em vez de mobile-first
7. **Tap targets <44px** (WCAG) em vários botões: filter pills (38px), copy buttons (38px), player buttons, admin actions (29px)
8. **`/home` com bug oculto:** `<style>` inline aplicava `grid-template-columns` num wrapper `display: contents` — wrapper sem box, regra silenciosamente ignorada. Stats 4-up esmagavam em phone há semanas.

Plano em 4 fases. Fases 1-3 entregues, Fase 4 pendente.

## Fase 1 — Fundação + shell + drawer + bottom nav + PWA

**Commit:** `46a118c` — `feat(mobile): Fase 1 — fundação mobile-first (shell + drawer + bottom nav + PWA)`

**Mudanças:**
- `app/layout.tsx`: `export const viewport` (device-width, viewport-fit=cover, theme-color light/dark) + `manifest: '/manifest.webmanifest'` + `appleWebApp`

  - `body { overflow: auto }` default; `body[data-shell="fixed"]` trava só em md+
  - `[data-mobile-only]` / `[data-desktop-only]` helpers com variants `data-as="flex|grid"`
  - `.btn { min-height: 44 }` (WCAG); `.btn-ghost { min-height: auto }` opt-out pra chips; `.btn-tap` opt-in
- `components/ui/Drawer.tsx` (novo): slide-in 220ms, backdrop blur, body scroll lock, ESC, focus trap, safe-area
- `components/shell/MobileHeader.tsx` (novo): sticky topo, hamburger 44×44, brand mark (variante admin pink)

- `components/shell/{Sidebar,AdminSidebar}.tsx`: WhatsappNavRow `min-height: 44`; "voltar pro app" usa `.btn-tap`

**Bugs encontrados durante implementação:**
- `display: 'flex'` inline em MobileHeader/BottomNav vencia `display: none` da CSS responsiva. Trocado por `data-as="flex"` com display delegado pro globals.css.
- Playwright defaults a prod via `PLAYWRIGHT_BASE_URL` em `.env.local` — local dev tests precisam de override explícito (`PLAYWRIGHT_BASE_URL=http://localhost:3001`).

## Fase 3 — `/home` + `/podcasts`

**Commit:** `6384f04` — `feat(mobile): Fase 3 — /home + /podcasts mobile-first`

**Mudanças `/home` (incluindo bug fix crítico):**
- `app/(app)/home/page.tsx`: removeu `<style>` inline desktop-first quebrado; classes mobile-first em `globals.css`
- `app/(app)/home/StatsRow.tsx`: `<div className="home-stats">` direto no grid (não num wrapper `display: contents`)
- `app/(app)/home/LastEpisodesGrid.tsx`: `className="home-episodes"` direto no grid
- `app/globals.css`: regras `.home-grid`, `.home-stats`, `.home-episodes` mobile-first (1-col / 2-up / 2-up); override em `@media (min-width: 48rem)` (2-col / 4-up / 4-up)

**Mudanças `/podcasts`:**
- Empty state grid `1fr auto` esmagava em phone → 1-col em <md, flips pra 2-col em md+ via `.podcasts-empty-state`
- `components/ui/CopyableCaption.tsx`: copy button `min-height: 44` + `padding: 10x18` (era ~38)
- `components/ui/SendToMenu.tsx`: em <md (768) o menu portalado spans a viewport (`left: 12, right: 12`) ao invés de tentar alinhar pela direita do botão (poderia sair da tela). MenuItem `min-height: 48`.

**Bug fix detalhado — `/home` stats:**

ANTES (bug oculto):
```jsx
// page.tsx
<style>{`@media (max-width: 900px) {
  .home-stats { grid-template-columns: repeat(2, 1fr) !important; }
}`}</style>

<div className="home-stats" style={{display: 'contents'}}>
  <StatsRow />  {/* StatsRow tinha grid 'repeat(4, 1fr)' hardcoded */}
</div>
```

`display: contents` não forma box, então `grid-template-columns` aplicado nele **não tem efeito**. O grid real (dentro de `<StatsRow>`) ficava 4-up em todas as larguras → esmagava em phone (4 cols × ~80px → labels truncados).

DEPOIS (fix):
```jsx
// StatsRow.tsx
<div className="home-stats">  {/* classe direto no grid container */}

// globals.css
.home-stats {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
}
@media (min-width: 48rem) {
  .home-stats { grid-template-columns: repeat(4, minmax(0, 1fr)); }
}
```

**Validação:** 25/25 Playwright local + 22/22 contra prod (4 fase3 + 3 approval + 11 audit + 4 shell).

## Fase 4 (PENDENTE) — admin no phone

**Por que ficou pra outra sessão:** Fases 1-3 cobriam o fluxo do USER tenant (Aprovar é o clique humano #1). Admin é uso interno do superadmin (você), pode ficar em uma 4ª fase isolada.

   - `suspender`, `deletar`, `senha`, `tirar SA`, `tornar SA`, `atribuir`, `desatribuir`, `ver` — todos em ~29h
   - Localização: dentro das table cells em `TenantsTable.tsx`, `UsersTable.tsx`, `UazapiTable.tsx`. Cada botão tem inline style com padding pequeno; aplicar `min-height: 44` ou substituir por `.btn` (que já tem o floor).

3. **Modais de criar/editar (CreateTenantModal, CreateUserModal, etc.):**
   - Layout vertical (label + input cada um em sua linha) em <md
   - Botões de ação ("salvar"/"cancelar") full-width em <sm

4. **Padrão de lista admin:**
   - Em <640px, cada row vira card com:
     - Linha 1: nome (forte) + status badge
     - Linha 2: detalhes (plano, criado, etc) em key:value pairs compactos
     - Linha 3: botões de ação 44px+ horizontais

**Como fazer (sugestão):**
- Adicionar regra `.admin-table-as-cards` em globals.css que vira `display: block` os `<table>`/`<tr>`/`<td>` em <640px (técnica clássica de "responsive table"). OU criar componente `<AdminEntityList>` que renderiza tabela em md+ e cards em <md (mais limpo).
